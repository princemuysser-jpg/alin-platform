منصة آلين v4.1.0 — إعادة بناء نظام المندوب

هذه النسخة تحتوي مسارين واضحين فقط:

أولاً: مشروعك الحالي الذي يحتوي بيانات
استخدم ملفاً واحداً فقط:
database/COURIER_REBUILD_V4_1_0.sql

هذا الملف:
- لا يحذف الطلبات أو الحسابات أو القيود المالية.
- ينشئ خدمة واحدة لتعيين المندوب من الإدارة.
- ينشئ خدمة واحدة لحركة طلب المندوب.
- يصلح فقط الطلبات القديمة التي لديها مندوب وبقيت بحالة جديد/بانتظار الإدارة.
- يعمل داخل Transaction؛ عند ظهور خطأ لا يثبت نصف التعديل.

ثانياً: مشروع Supabase جديد وفارغ تماماً
استخدم:
ALIN_V4_CLEAN_PROJECT_MASTER.sql

ممنوع تنفيذ ملف Clean Master على مشروعك الحالي. الملف نفسه يتوقف إذا وجد جداول آلين.

التنفيذ على مشروعك الحالي:
1) خذ نسخة احتياطية من Supabase ومن ملفات الموقع.
2) افتح database/COURIER_REBUILD_V4_1_0.sql في SQL Editor واضغط Run مرة واحدة.
3) يجب أن تكون النتيجة الأخيرة:
   assignment_rpc_ready = true
   transition_rpc_ready = true
   courier_workflow_version = 4.1.0
4) ارفع محتويات هذه النسخة كاملة إلى الموقع بدل ملفات النسخة الحالية.
5) افتح الموقع بنافذة خاصة أو اضغط Ctrl+F5.
6) اختبر طلباً جديداً بهذا التسلسل:
   تحويل للمندوب ← قبول الطلب ← استلمت الطلب ← بدء التوصيل ← تم التسليم واستلام المبلغ.

لا تنفذ أي ملف SQL قديم خاص بالمندوب، ولا ترفع مجلد hotfixes، ولا تنشر Edge Function باسم admin-assign-order.

المساعد الموجود:
ابدأ_تحديث_المندوب_v4_1_0.cmd
يفتح لوحة Supabase وينسخ ملف SQL الصحيح إلى الحافظة، لكنه لا ينفذ شيئاً تلقائياً.
